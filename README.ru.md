# base-agent

Локальный агент для работы с заметками. Это чат в терминале с одной папкой проекта: папкой Obsidian или любой другой папкой с файлами. Агент читает файлы проекта, отвечает по ним и создаёт новые заметки. Сфера работы задаётся ролью (инженер, наставник, редактор и т. д.), и новая роль — это просто новый файл. Язык, на котором говорит агент, задаётся в его настройках.

Агент — один файл на Python. Ставить пакеты не нужно, модели работают локально, данные никуда не уходят.

Команды и сообщения программы — на английском.

## Что нужно

- **Python 3.9 или новее.** Только стандартная библиотека, `pip install` не нужен.
- **Локальный сервер моделей с OpenAI-совместимым API.** По умолчанию это [Docker Model Runner](https://docs.docker.com/ai/model-runner/), но подойдут Ollama, llama.cpp server, LM Studio и другие.
- **Две модели:**
  - для ответов: по умолчанию Qwen3.8-27B (Q4_K_M, около 18 ГБ). Нужно примерно 24 ГБ свободной оперативной памяти (Mac) или видеопамяти;
  - для поиска по смыслу: по умолчанию Qwen3-Embedding-0.6B (около 0,6 ГБ).

  На машине со слабым железом можно указать в `.env` модель поменьше.

## Установка

### 1. Скачать агента

Скопируй папку `base-agent` в любое место. Все файлы агента лежат в ней, пути к ним вычисляются от расположения `agent.py`.

### 2. Запустить сервер моделей (Docker Model Runner)

**macOS и Windows** — Docker Desktop 4.40 или новее:

```bash
docker desktop enable model-runner --tcp 12434
```

**Linux** — Docker Engine с плагином Model Runner:

```bash
sudo apt-get install docker-model-plugin
```

Скачать модели:

```bash
docker model pull huggingface.co/ggml-org/qwen3.8-27b-gguf:Q4_K_M
docker model pull huggingface.co/qwen/qwen3-embedding-0.6b-gguf:Q8_0
docker model ls
```

Проверить, что сервер отвечает:

```bash
curl http://localhost:12434/engines/v1/models
```

Если используется другой сервер (Ollama, llama.cpp, LM Studio), достаточно скачать модели в нём и указать адрес и названия в `.env` (см. ниже).

### 3. Настроить

```bash
cd base-agent
cp .env.example .env
```

Отредактируй `.env` и `settings.json` (см. раздел «Настройки»). Если всё по умолчанию (Docker Model Runner и модели выше), `.env` можно не создавать.

### 4. Запустить

```bash
python3 agent.py "/путь/к/папке/проекта"
python3 agent.py "/путь/к/папке/проекта" --role study
python3 agent.py "Мой проект"
```

Третий вариант работает, если в `.env` задана `PROJECTS_DIR`: относительный путь ищется внутри неё.

Без пути программа спросит его и запомнит: в следующий раз хватит нажать Enter. Папку можно перетащить в терминал из файлового менеджера. Если папки нет, программа предложит её создать вместе с недостающими папками выше: так можно начать новый проект прямо из агента.

## Настройки

Все файлы настроек лежат рядом с `agent.py`.

### `.env` — сервер, модели, папка проектов

Пример — в `.env.example`.

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `MODEL_BASE_URL` | адрес OpenAI-совместимого сервера моделей | `http://localhost:12434/engines/v1` (Docker Model Runner) |
| `MODEL` | модель для ответов | `huggingface.co/ggml-org/qwen3.8-27b-gguf:Q4_K_M` |
| `EMBED_MODEL` | модель эмбеддингов для поиска | `huggingface.co/qwen/qwen3-embedding-0.6b-gguf:Q8_0` |
| `PROJECTS_DIR` | папка с проектами, относительно которой понимаются короткие пути | не задана |

Адреса других серверов: Ollama — `http://localhost:11434/v1`, llama.cpp server — `http://localhost:8080/v1`, LM Studio — `http://localhost:1234/v1`.

Формат `.env` — строки `ИМЯ=значение`, комментарии начинаются с `#`, кавычки вокруг значения необязательны. Переменная, заданная в терминале (`MODEL=… python3 agent.py …`), важнее значения из `.env`. Файл `.env` личный и в `.gitignore` уже исключён.

### `settings.json` — имя и язык агента

```json
{
 "name": "Лёха",
 "language": "Russian"
}
```

- `name` — под этим именем агент подписывает ответы, и модель знает, как её зовут.
- `language` — язык, на котором говорит агент, в том числе в создаваемых файлах. Подойдёт любое название языка, понятное модели: `Russian`, `English`, `German`, `русский`… Если пусто, агент отвечает на том языке, на котором ему пишут.

Файл перечитывается перед каждым ответом: изменения действуют без перезапуска. Если файла нет или он испорчен, агента зовут «Agent», и он отвечает на языке собеседника.

### Роль проекта

Роль запоминается для каждого проекта отдельно. При первом открытии проекта программа покажет список ролей и спросит, какую взять (Enter — `general`). Флаг `--role` выбирает роль при запуске и запоминает её, команда `/role` меняет её в чате.

## Команды в чате

Строка ввода начинается с `>`, ответ агента — с его имени: `Лёха> …`.

| Команда | Что делает |
|---|---|
| `/files` | список файлов проекта, которые читает агент; отмечает те, из которых текст извлечь не удалось |
| `/role` | показать текущую роль и список ролей |
| `/role <имя>` | сменить роль (разговор продолжается) |
| `/save` | сохранить последний ответ в новый файл |
| `/transcript` | сохранить весь текущий разговор в проект новой заметкой |
| `/reset` | начать новый разговор; прежний уходит в архив, а не удаляется |
| `/exit` или Ctrl+D | выйти; разговор сохранён |

Пока модель не начала отвечать, в терминале крутится индикатор с секундами (`⠹ Лёха is thinking… 4 s`); то же при правке черновика и индексации заметок. Ctrl+C во время ожидания или ответа прерывает его.

## Роли

Роли лежат в папке `roles/`, по одному файлу `.md` на роль. Имя файла — имя роли для `--role` и `/role`. Готовые роли:

- `general` — помощник по заметкам: ответы, сводки, планы, конспекты;
- `engineer` — инженер-электронщик;
- `study` — наставник: объясняет, делает конспекты и карточки, проверяет решения с подсказками;
- `editor` — литературный редактор текстов.

Чтобы добавить роль, создай новый файл в `roles/`, например `roles/lawyer.md`:

```markdown
---
search: Find a passage from the contract or notes that helps answer the question
---
You are a legal consultant. Rely on the documents in the project, cite specific clauses, never invent laws. If the question needs professional legal advice, say so.
```

- `search` — инструкция для смыслового поиска: что искать в заметках. Если строки нет, берётся общая.
- Текст после `---` — характер и правила этой сферы. Имя и язык в нём писать не нужно: их агент получает из `settings.json`. Текст ставится в начало инструкций модели, перед общими правилами из `prompt.md`.

Роли и `prompt.md` написаны по-английски: модели лучше следуют английским инструкциям, а модель поиска рассчитана на английскую инструкцию. На язык ответов это не влияет, он берётся из `settings.json`. Роль можно написать и по-русски, она тоже будет работать. Файл роли перечитывается перед каждым ответом, поэтому правки действуют сразу.

## Что умеет

- **Читает проект.** Перед каждым ответом перечитывает с диска файлы проекта, кроме скрытых (`.obsidian`, `.trash`) и временных файлов Office (`~$…`). Правки, сделанные в редакторе, видны сразу. Форматы:
  - как текст: `.md`, `.txt`, `.csv`, `.tsv`, `.json`, `.yaml`, `.yml`, `.toml`, `.ini`, `.cfg`, `.conf`, `.log`, `.xml`, `.tex` и код (`.py`, `.c`, `.h`, `.cpp`, `.hpp`, `.ino`, `.js`, `.ts`, `.sh`, `.sql`);
  - `.xlsx` — все листы построчно, ячейки через табуляцию; `.pptx` — текст по слайдам;
  - `.pdf` — через `pdftotext`, если он установлен (macOS: `brew install poppler`, Linux: `sudo apt install poppler-utils`), иначе на macOS через встроенный PDFKit. Из сканов без текстового слоя текст не извлекается;
  - `.docx`, `.doc`, `.rtf`, `.odt`, `.html`, `.htm` — через `textutil`, который есть **только в macOS**. На Linux и Windows эти файлы пока пропускаются (в `/files` они отмечены как нечитаемые).

  Из одного файла берётся не больше 300 000 символов. Извлечённый текст запоминается, пока программа запущена, поэтому PDF и документы разбираются заново только после изменения.
- **Ищет по смыслу.** Если всё содержимое проекта короче 8000 символов, модель получает его целиком. Если длиннее — текст режется на куски примерно по 1200 символов (длинные таблицы и логи — по строкам), и модель получает 6 самых похожих на вопрос (инструкция поиска берётся из роли). Векторы кешируются в `.cache/`, пересчитываются только изменённые куски. Если модель эмбеддингов недоступна, агент берёт начало заметок.
- **Создаёт новые файлы.** Модель кладёт черновик в блок `~~~file: Папка/Название` и сама предлагает название. После ответа программа спрашивает: `Create file "Папка/Название.md"? Enter = create, or type your remarks`.
  - **Enter** — файл создаётся с предложенным названием, даже если модель задала уточняющие вопросы.
  - **Замечания** (или ответы на вопросы модели) — модель правит черновик, но не выводит его заново: программа показывает только изменения (`+` добавлено, `−` убрано; в терминале зелёным и красным) и снова предлагает создать файл. Так можно повторять сколько нужно.
  - **`/name <название>`** — другое название, **`/cancel`** (или Ctrl+C) — не создавать.

  `.md` добавляется сам. Файл создаётся только внутри папки проекта. Существующий файл не перезаписывается никогда: если название занято, к нему добавляется « 2», « 3». Если модель не предложила название, берётся первый заголовок текста или «Note <дата>». Блок может быть и в ``` вместо `~~~`. Если пользователь просил записать, а блока в ответе нет, программа так и скажет и предложит `/save` — там работает то же предложение с названием и замечаниями. `/transcript` предлагает название «Conversation <дата время>».
- **Сохраняет разговоры.** Разговор с каждым проектом записывается на диск после каждого ответа и продолжается при следующем запуске: программа покажет, сколько в нём сообщений и какой был последний вопрос. Модель видит последние 20 сообщений, на диске хранится весь разговор. `/reset` убирает разговор в архив, `/transcript` сохраняет его в проект заметкой.

Чего нет: изменения, дописывания и удаления существующих файлов, поиска за пределами папки проекта, распознавания текста на картинках и сканах, веб-интерфейса.

## Платформы

- **macOS** — работает полностью.
- **Linux** — работает всё, кроме чтения `.docx`, `.doc`, `.rtf`, `.odt`, `.html`. Для PDF нужен `poppler-utils`.
- **Windows** — не проверялся. Код рассчитан на любую ОС, ограничения те же, что на Linux. Для PDF нужен `pdftotext` из poppler в `PATH`. Индикатор ожидания требует терминала с поддержкой ANSI (Windows Terminal).

## Устройство

| Файл | Что внутри |
|---|---|
| `agent.py` | весь код: настройки, модели, роли, чтение файлов, создание файлов, разговоры, чат |
| `.env` / `.env.example` | сервер, модели, папка проектов; `.env` — личный, `.env.example` — образец |
| `settings.json` | настройки агента: имя и язык |
| `prompt.md` | общие правила для модели в любой роли: работа с заметками и создание файлов |
| `roles/` | роли: по файлу на сферу |
| `.cache/` | векторы заметок, последний открытый проект, роли проектов (`agents.json`) |
| `.cache/chats/` | разговоры по проектам; `archive/` — после `/reset` |
| `.gitignore` | исключает из git `.env`, `.cache/` и `backups/` |
| `README.md` / `README.ru.md` | эта инструкция на английском / русском |

Один шаг агента: вопрос → перечитывается файл роли, к нему добавляются имя и язык агента из `settings.json` → `context()` собирает список файлов и нужные куски → `chat()` отправляет роль, общие правила, заметки и историю модели и печатает ответ → `create_files()` находит в ответе блоки `~~~file`, `offer_file()` предлагает создать каждый с названием от модели и по замечаниям правит черновик через `make_reviser()` → разговор записывается на диск.

Удалять `.cache/` безопасно только частично: векторы пересчитаются сами, но в `chats/` лежат разговоры, а в `agents.json` — роли проектов.
